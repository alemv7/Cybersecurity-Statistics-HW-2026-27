HW 03 · Toy ECC vs Caesar

Alessandro Bertoldi · Statistics in Cybersecurity. Encrypt the same message with a toy secp256k1 scheme and with the Caesar cipher, then attack both: statistics against Caesar, key-space search against the toy ECC.

00Message used in all experiments

Everything runs in your browser. The toy ECC uses the real secp256k1 curve (y² = x³ + 7 over a 256-bit prime), but the private key is restricted to a small range.

01Toy ECC encryption (ECIES-style)

Algorithm and role of the keys

  • Private key k (secret, small integer): lets the receiver decrypt. Public key Q = k·G (published): lets anyone encrypt. Computing Q from k is easy, the reverse is the ECDLP.
  • Ephemeral key r (random, fresh for each message, full 256 bits) with R = r·G sent along with the ciphertext.
  • Shared secret S = r·Q = k·R = rk·G: the sender computes it from r and Q, the receiver from k and R (Diffie-Hellman). An eavesdropper sees only Q and R.
  • Key stream: Keccak-256(S.x ‖ counter) blocks. Ciphertext = plaintext XOR key stream. Decryption repeats the XOR with the same stream.

02Caesar cipher

Each letter is moved shift positions forward in the alphabet (mod 26); case and non-letters are kept. Decryption moves letters back by the same amount.

04Statistical cryptanalysis of Caesar

Idea: a Caesar key moves the whole letter distribution of the language. Build a reference profile from a known-language corpus, then for each of the 26 possible shifts decrypt and measure how well the result matches the profile. The best score gives the key.

06Discussion

Caesar vs toy ECC: similarities and differences

Both are reversible, keyed transformations where the receiver undoes what the sender did using a secret. Differences: Caesar is symmetric and deterministic, one key for both parties, and keeps the structure of the language (a monoalphabetic substitution), so statistics are enough to break it. The toy ECC is asymmetric: the receiver's secret never leaves them, a fresh r randomizes every ciphertext, and a hash-based key stream removes statistical structure. The ciphertext bytes look uniform whatever the plaintext is. Its weakness is not statistical but the size of the key space.

Statistical attack vs key-space attack

The statistical attack uses information leaked by the ciphertext: it needs enough text to see the distribution and tests only 26 candidates, so its success grows with length (see the experiment). The ECC attack ignores the ciphertext statistics entirely, which are useless: it solves the discrete logarithm of Q within a small interval and then decrypts exactly, with no probability of error and no need for long messages. Baby-step giant-step needs about 2^(bits/2) group operations and memory, against 2^bits for exhaustive search.

Why it fails against a properly configured ECC

With k uniform in a ~2^256 range, the best known generic attacks (BSGS, Pollard's rho) need about 2^128 group operations, which after the extrapolation shown in section 05 is far beyond any feasible computation. No statistical shortcut exists because S passes through a hash and r changes each time. The key size is therefore the security parameter.

Weaknesses from the restricted key space vs from the design

  • From the key space: exhaustive search, BSGS, Pollard's kangaroo (made for known intervals), and any key that is guessable or low-entropy.
  • From the design of the toy scheme: no authentication (the ciphertext is malleable: flipping a ciphertext bit flips the same plaintext bit, so a MAC or AEAD is needed); no check that R lies on the curve (invalid-curve attacks); a reused r would reuse the key stream (c₁ ⊕ c₂ = m₁ ⊕ m₂); no domain separation or salt in the KDF; the message length leaks; no padding or versioning.
